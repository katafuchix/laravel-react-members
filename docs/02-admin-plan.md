# 管理者（Admin）機能の構築計画

Rails の `rails g devise Admin` と同様に、会員（`User`）とは別モデル・別ログインの管理者を作る。
1ステップずつ確認しながら進める。作業ブランチは `dev`。

## 方針（A1 で決定）

| 項目                       | 決定                                                      |
| -------------------------- | --------------------------------------------------------- |
| 方式                       | 別モデル `Admin`（別テーブル `admins`、別ガード `admin`） |
| 管理者のメール認証         | 今は不要                                                  |
| 管理者のパスワードリセット | 今は不要（ログインのみ）                                  |
| 管理者の登録               | 公開の登録画面は作らない。**Artisan コマンド**で作成する  |
| 最初に作る管理画面         | 会員一覧（その後、必要に応じて編集、削除）                |

## 設計

| 要素         | 内容                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------- |
| テーブル     | `admins`（`id`、`name`、`email`（ユニーク）、`password`、`remember_token`、`timestamps`）   |
| モデル       | `App\Models\Admin`（`Authenticatable`）。`MustVerifyEmail` や 2要素認証、パスキーは使わない |
| ガード       | `config/auth.php` に `admin`（`session` ドライバー、プロバイダー `admins`）を追加           |
| ルート       | `/admin/login`、`/admin/logout`、`/admin/dashboard`、`/admin/users`（会員一覧）             |
| ミドルウェア | 管理者用の画面は `auth:admin`。ログイン画面は `guest:admin`                                 |
| 画面         | React（Inertia）。`resources/js/pages/admin/` に置く                                        |
| 作成コマンド | `php artisan admin:create`（名前、メール、パスワードを対話で入力）                          |

### Fortify を流用しない理由

- Fortify はデフォルトのガード（`web`）のユーザー向けに作られている。
- 管理者のログイン処理は、専用のコントローラーで作る方が単純で、会員側の認証に影響しない。

### 設計上の注意

- ログアウトでは、セッション全体を破棄せず、`admin` ガードのログアウトとトークンの再生成だけを行う。セッション全体を破棄すると、同じブラウザで会員としてログイン中の状態も消えるため。
- 会員用のサイドバーは `auth.user`（会員）を前提にしているため、管理画面では使わず、専用の簡易レイアウトを作った。
- Wayfinder の型付きルートは、`php artisan wayfinder:generate` ではなく **`php artisan wayfinder:generate --with-form`** で生成する。`--with-form` を付けないと、`.form()` が消えて、会員側の画面も含めて型エラーになる（`composer run dev` で動く Vite のプラグインは `formVariants: true` で生成する）。

## A5 の記録

### 使い方

```
php artisan admin:create
php artisan admin:create --name="Admin User" --email=admin@example.com
```

| 項目         | 内容                                                                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入力         | 名前、メール、パスワード、確認用パスワードを対話で入力（パスワードは画面に表示されない）                                                                                            |
| オプション   | `--name`、`--email` は引数でも渡せる。省略した項目は対話で入力する                                                                                                                  |
| パスワード   | **引数では受け取らない**（シェルの履歴に残るため）。必ず対話で入力する                                                                                                              |
| 非対話モード | `--no-interaction` では実行を拒否する（パスワードを入力できないため）                                                                                                               |
| 検証         | 名前は必須・255文字以内。メールは形式、255文字以内、`admins` 内で重複不可。パスワードは会員側と同じ強度（本番は12文字以上、大小文字・数字・記号、漏えい済みは不可。本番以外は緩い） |
| 保存         | パスワードは `Admin` モデルの `hashed` キャストでハッシュ化される                                                                                                                   |

### 確認中に見つかった不具合と修正

- **症状**: 管理者でログインすると、管理画面ではなく会員のログイン画面（`/login`）に飛ばされた。
- **原因**: 「ログイン後に戻る URL」（`url.intended`）は、会員側と管理者側で共有のセッションに入る。管理者のままで会員側の `/dashboard` を開いて `/login` に飛ばされたとき、戻り先として `/dashboard` が残り、次の管理者のログインがそこへ戻ってしまった。
- **修正**: `AdminSessionController` で、戻り先が `/admin` 配下のときだけ使い、それ以外は `/admin/dashboard` にする。
- **確認**: 先にテストで再現し（失敗）、修正後に通ることを確認した。ブラウザでも確認した。
- **残る制約**: 逆向きは未対応。管理者用の画面を未ログインで開いた後に、会員としてログインすると、戻り先の `/admin/...` に飛んで、管理者のログイン画面に戻される。会員のログインは Fortify の処理なので、手を加えていない。
