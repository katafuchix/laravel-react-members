# 作業の振り返り

Laravel 公式の React スターターキットで、Devise 相当の会員制システムを作り、別モデルの管理者（Admin）機能まで追加した作業のまとめ。

## 成果

| 項目       | 内容                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------- |
| ベース     | Laravel 13.43.0 + React スターターキット（React 19、TypeScript、Inertia 3、Fortify）                |
| 会員機能   | 会員登録、ログイン、パスワードリセット、メール認証、2要素認証、パスキー、設定画面（キット標準）     |
| 認証メール | Resend 経由で送信。受信とリンクでの認証まで確認済み                                                 |
| 管理者機能 | 別モデル `Admin`、別ガード `admin`、ログイン、ダッシュボード、会員一覧、作成コマンド `admin:create` |
| テスト     | PHPUnit 66件（キット付属 42件 + 追加 24件）                                                         |
| CI         | GitHub Actions（キット付属）。PR #1 でマージ済み                                                    |

## 作業の流れ

### 会員制システムのベース（`docs/00-plan.md`）

| Step | 内容                                                                             |
| ---- | -------------------------------------------------------------------------------- |
| 0    | 環境確認（PHP 8.5.12、Composer 2.10.2、Node 22）と調査                           |
| 1    | Laravel インストーラの導入（v5.33.0）                                            |
| 2    | `laravel new` で React キットのプロジェクトを作成（SQLite、PHPUnit、Boost あり） |
| 3    | 開発サーバーを起動し、登録・ログイン画面を Chrome で確認                         |
| 4    | メール認証の動作確認（キットで設定済み。追加実装は不要だった）                   |
| 5    | Resend の導入（SDK、`.env`）                                                     |
| 6    | Resend 経由で認証メールを送信し、受信とリンクでの認証を確認                      |

### 管理者機能（`docs/02-admin-plan.md`）

| Step | 内容                                                                 |
| ---- | -------------------------------------------------------------------- |
| A1   | 方針の決定（別モデル、ログインのみ、作成はコマンド、最初は会員一覧） |
| A2   | `admins` テーブルと `Admin` モデル                                   |
| A3   | `admin` ガードを `config/auth.php` に追加                            |
| A4   | 管理者のログイン、ログアウト（コントローラー、ルート、React の画面） |
| A5   | `php artisan admin:create`（パスワードは対話入力のみ）               |
| A6   | 管理画面のダッシュボード（会員数の集計）と会員一覧（ページ送り）     |
| 公開 | commit、push、PR 作成、CI の確認、マージ（`dev` は残す）             |

## 構成の全体像

| 区分                            | 会員（User）                  | 管理者（Admin）                           |
| ------------------------------- | ----------------------------- | ----------------------------------------- |
| ガード                          | `web`                         | `admin`                                   |
| テーブル                        | `users`                       | `admins`                                  |
| ログイン画面                    | `/login`                      | `/admin/login`                            |
| 登録                            | 公開の登録画面（`/register`） | 公開の登録画面なし。`admin:create` で作る |
| 認証の実装                      | Fortify（キット標準）         | 専用のコントローラーとフォームリクエスト  |
| メール認証、2要素認証、パスキー | あり                          | なし                                      |
| ログイン試行の制限              | 1分5回まで                    | 1分5回まで（同じ値）                      |
| 画面のレイアウト                | サイドバー付き（`AppLayout`） | ヘッダーのみの簡易版（`AdminLayout`）     |

- 会員と管理者はセッションを共有するが、ログイン状態はガードごとに別々に管理される。
- 管理者でログインしても、会員側の画面（`/dashboard` など）には入れない。逆も同じ。

## よく使うコマンド

| 目的                    | コマンド                                                                                                               |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 開発サーバーの起動      | `composer run dev`                                                                                                     |
| 管理者の作成            | `php artisan admin:create`                                                                                             |
| テストの実行            | `php artisan test`                                                                                                     |
| CI と同じ全チェック     | `composer ci:check`（PHPStan のメモリ不足になる環境では、`vendor/bin/phpstan analyse --memory-limit=1G` を単独で実行） |
| 型付きルートの再生成    | `php artisan wayfinder:generate --with-form`（**`--with-form` を必ず付ける**）                                         |
| コードの整形（PHP）     | `vendor/bin/pint`                                                                                                      |
| 整形と lint（JS / md）  | `npm run check`（自動修正は `npm run check:fix`）                                                                      |
| TypeScript の型チェック | `npm run types:check`                                                                                                  |
| テストのひな形          | `php artisan make:test Admin/FooTest`（`Feature` は付けない）                                                          |

## CI とテスト

| 項目                   | 内容                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| CI の正体              | キットが用意した GitHub Actions（`.github/workflows/tests.yml`）。Laravel の機能ではない                |
| 動くタイミング         | `main` への push と、すべての PR                                                                        |
| 実行内容               | `composer setup` のあと `composer ci:check`（`npm run check`、`npm run types:check`、`composer test`）  |
| `composer test` の中身 | Pint、PHPStan、`php artisan test`                                                                       |
| テストの探し方         | `phpunit.xml` の設定どおり、`tests/Unit` と `tests/Feature` の下にあるクラスを自動で実行する            |
| テスト時の環境         | DB は SQLite の `:memory:`、メールは `array`（実際には送らない）、キューは `sync`、セッションは `array` |
| テストのひな形         | `make:test` が作るのは空のサンプルだけ。何をどう確かめるかは自分で書く                                  |
| 範囲外                 | ブラウザでの手動確認（Chrome での確認）は CI では実行されない                                           |

## つまずきと対策

| 場面             | 症状                                                                     | 原因                                                                                   | 対策                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| プロジェクト作成 | `laravel new .` で「`--force` は使えない」「Application already exists」 | カレントディレクトリへの作成では `--force` が使えない                                  | 親ディレクトリからプロジェクト名を指定し、`--force` を付けて実行                                                                        |
| メール送信       | 認証メールが届かない                                                     | `.env` を変更する前に起動した開発サーバーが、古い設定（`MAIL_MAILER=log`）のままだった | `.env` を変更したら、開発サーバーを再起動する。`laravel.log` に `From: ...@example.com` のメールが出ていたら、Resend には送られていない |
| メール送信       | 他の人に認証メールを送れない                                             | `onboarding@resend.dev` は、Resend の登録アドレス宛てにしか送れない                    | 独自ドメインを Resend で検証し、`MAIL_FROM_ADDRESS` を変更する（未対応）                                                                |
| 環境変数         | `.env` に別プロジェクトの設定（`RESEND_FROM_EMAIL` など）が混ざっていた  | Laravel では使われない変数                                                             | 削除し、`MAIL_MAILER` と `MAIL_FROM_ADDRESS` を使う                                                                                     |
| 型付きルート     | 全画面で `.form` がないという型エラー                                    | `wayfinder:generate` を `--with-form` なしで実行した                                   | `--with-form` 付きで再生成                                                                                                              |
| 管理者のログイン | ログイン後に会員のログイン画面へ飛ばされた                               | 「ログイン後に戻る URL」が会員側と共有で、古い会員側の URL が残っていた                | `/admin` 配下の戻り先だけを使う。先にテストで再現してから修正した                                                                       |
| CI               | PHPStan が `Admin                                                        | User` 型でエラー                                                                       | 認証のプロバイダーが2つになった                                                                                                         | 会員専用のコントローラーで `@var User` を付けて型を明示 |
| CI               | `npm run check` が `docs/` の md を指摘                                  | md の表の桁そろえが、整形ルールに合っていない                                          | `npm run check:fix` で整形（push 前に `npm run check` で確認）                                                                          |
| ローカル確認     | PHPStan が「メモリ上限 128M」で停止                                      | ローカルの PHP のメモリ設定                                                            | `--memory-limit=1G` を付ける                                                                                                            |
| 情報管理         | テスト用パスワードを書いたシーダーが、公開リポジトリの履歴に残った       | ファイルをコミットする前に、公開状態を確認しなかった                                   | ファイルは削除した。履歴には残るため、該当するローカルのパスワードを変更する                                                            |

### 教訓

- 作業の最後に、手元で `composer ci:check` と同じ範囲を確認する。一部だけ（`npm run types:check` のみ）では、CI で別のエラーが出る。
- 認証情報は、ファイルに書く前に、そのファイルが公開されるかを確認する。
- 設定ファイル（`.env`）を変更したら、起動中のサーバーを再起動する。
- テストを先に書いて失敗を確認してから直すと、原因の特定と再発防止に役立つ（ログイン後の戻り先の不具合）。

## 未対応・次の候補

| 項目                                                                        | 内容                                                                                                                                            |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 独自ドメインでの送信                                                        | Resend でドメインを検証し、`MAIL_FROM_ADDRESS` を変更する。これがないと、他の人に認証メールが届かない                                           |
| 会員の検索・編集・削除                                                      | 管理画面の機能追加                                                                                                                              |

| `trackable` 相当（ログイン日時など）、`lockable` 相当（アカウントのロック） | デフォルトにない                                                                                                                                |
| 画面の日本語化                                                              | 画面の文言は英語のまま                                                                                                                          |
| 逆向きの戻り先の問題                                                        | 管理者用の画面を未ログインで開いたあと、会員としてログインすると、管理者のログイン画面に戻される（会員のログインは Fortify の処理なので未対応） |
| ローカルのパスワード変更                                                    | 公開された履歴のパスワードを使っているローカルの2ユーザー                                                                                       |
